# B-175 — Jobs, places and the company's lists (slice 1 of B-167)

Settled 2026-10-30 before the first edit; built as written.

- **Job** (CoreHR, per tenant): title (≤150, unique per tenant ignoring case and spacing), optional family, optional level, both values of company lists ("Job families", "Levels", ordered). Not effective-dated: the catalogue isn't history, people's changes are. A renamed job shows its new name on everyone's job and job history; a change record keeps the names it was made with (it is that record's own account), plus the job and place ids so an edit starts from the same picks.
- **Place**: name (≤100, unique per tenant), optional city and country as text (rung 1).
- **References**: `WorkAssignment.JobId` (required) and `PlaceId`, `OpenRole.JobId` and `PlaceId`, `Employment.EmploymentTypeId`. The text columns stay as display copies the catalogue keeps in step (rename and merge rewrite them in the same save), so the many readers, Performance's snapshot, Identity and Learning keep reading the same strings. The domain refuses another tenant's job, place or value.
- **Retire, merge, delete**: a used job or place is retired (out of pickers, kept where held) or merged; one never used can be deleted. Merging moves every assignment and open role to the kept one and removes the other, recorded in Change history. Places alike.
- **Lists**: five fixed lists (employment types, levels, job families, change reasons, leave types); values have a stable key and a label, ordered; used values retire, unused ones delete; no translations (C3 rung 1). Defaults seeded once per company on first read (a seed marker, so emptying a list never brings them back); no default families. Change reasons and leave types have no consumer yet (B-179, B-180).
- **Writes** take ids: hire, add existing, job change, rejoin, open roles, legacy create/update/rehire. The workforce import resolves or creates by name until B-186.
- **Authorization**: read = organization view, employee view or manage, or people-data settings view; jobs and places = `core.organization.manage`; lists = people-data settings manage.
- **Screens**: Jobs and Places as lenses of Organization (`/core/organization/jobs|places`), Lists as a Settings › Core HR section (`/core/settings/lists`). Employment type stays off the hire and rejoin forms (an earlier product call held by tests; B-196).
- **Migration** `20261030163220_AddJobsPlacesAndLists`: per tenant, titles grouped by trimmed single-spaced case-insensitive form (most common spelling names the job) become jobs, locations places, employment-type texts list values; Down drops the new columns and tables, the text was never removed.
