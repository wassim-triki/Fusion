Agreed, 2026-11-06

Direction B and every state here. The build plan is plans/B-302-error-pages.md.

Decided

  • Direction B, a small drawing per state, your pick over the other two.
  • DESIGN.md changes with it. It rules out oversized illustrations, so it gains a line allowing one small drawing on failure pages. Ordinary empty states keep the old rule.
  • One component. Today there are at least five treatments. One PageState in the design system would replace them all, in Core HR, Performance, Platform and the shell.

The same in every state

  • No dashed box, no status codes. Plain words, and the sidebar stays so nobody feels thrown out.
  • Never a dead end. One clear next step and one way out.
  • Nothing leaks. A refusal never names the record, repeats an ID from the address or says which role would open it.
  • Colleague modules are left alone. Learning, Recruitment, Interview and Onboarding keep their own pages.

Built in from the start, if you agree

  • Name the real administrators. Needs a small read of who administers the company. An employee learns no more than the directory already shows.
  • A reference code on failures. Next.js already gives us one. The person can copy it and send it to you.
  • Retrying by itself when a module is down or you're offline, so the page comes back without a click.

Left out on purpose

  • A "Request access" button with approvals. Good products have it, but it's a whole feature with its own inbox. "Email Amira" gets most of the value now. I'd board the rest.
  • Jokes. People reach these pages when they're stuck, often over their own pay or review.
  • Ordinary empty states. "No reviews yet" isn't a failure, so those stay as they are for now.

Where this came from

I couldn't find BambooHR's own error screens: they aren't documented publicly and its website only returned a bare 404 to my fetch. So the BambooHR influence comes from its 2024 redesign as recorded in our design direction: warm type, rounded shapes, people first. It isn't a copy of a specific page.

The access rules come from AppMaster on access denied patterns: plain words, one next action, no restricted detail, a reference code. Plain language with no status codes comes from How to Design Better Error Pages. A non-blaming tone comes from the Alberta design system. Using a drawing only when it helps understanding comes from eBay's Playbook. Administrators naming a contact on a 403 comes from Frontify.
